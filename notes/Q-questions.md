# Q 단계: 원문 편집 — 결정과 확인 필요

## 정한 것
- **화면**: 도구줄 ✎ 단추(Ctrl+E)를 누르면 탭이 두 칸. 왼쪽 원문 편집기, 오른쪽 미리보기(반반, 경계를 끌어 조절).
  다시 누르면 닫는다. 고친 것이 있으면 닫을 때(탭·창·편집기) 저장할지 묻는다. 고친 탭은 제목 앞에 ●.
- **편집기**: CodeMirror 6 을 `tools/editor` 에서 하나로 묶은 `htex/viewer/editor.js` (약 0.6MB, 압축 0.2MB).
  문법 강조(tex·htex 는 stex, Markdown, HTML), 줄 번호, 괄호 짝, 접기, 찾기·바꾸기(편집기에 초점이 있을 때 Ctrl+F),
  되돌리기, 줄 바꿈 표시. 밝게·어둡게는 창 테마를 따른다. 찾기 상자 글자는 한국어 화면에서 한국어.
- **미리보기**: 입력을 0.3초 멈추면 `core.set_draft(주소, 원문)` 로 고친 원문을 넣고 미리보기만 다시 그린다
  (스크롤·슬라이더 유지, 원격 문서를 다시 가져오지 않음). 진단(오류·경고)은 편집기 줄 옆에 표시.
  편집 중 미리보기의 다른 문서 링크와 주소창 이동은 새 탭으로 연다 (편집하는 문서를 떠나지 않게). 뒤로·앞으로는 막는다.
- **보안**: 편집기는 별도 페이지(htexapp://editor/)이고 QWebChannel 의 bridge 객체는 그 페이지에만 준다.
  문서 페이지(미리보기·다른 탭)의 스크립트는 저장 기능에 닿지 않는다. 파일 쓰기는 Python 쪽에서 사용자가 연 파일과
  저장 대화상자에서 고른 경로(그리고 그 아래 같은 상대 위치)에만.
- **로컬 저장**(Ctrl+S): UTF-8 만 편집 (아니면 거절). BOM·줄바꿈(CRLF)은 읽은 대로 되살려 저장.
  같은 폴더 임시 파일에 쓰고 바꿔치기, 권한 유지. 읽은 뒤 다른 프로그램이 바꿨으면 덮어쓸지 묻는다.
  이번 실행에서 처음 저장할 때 원본을 캐시 폴더 `backups/` 에 복사 (30일 지난 것은 지움).
  고친 것이 없을 때 밖에서 파일이 바뀌면 편집기도 새 내용으로.
- **원격 문서**: 서버에는 쓸 수 없으므로 Ctrl+S 도 "다른 이름으로 저장". 본문과 함께 상대 주소로 부르는
  `\input`·`\include`·`\usemacros`·`\usestyle`·`.bbl`·그림을 같은 서버에서 가져와 고른 폴더에 같은 상대 위치로 쓴다.
  확장자 없는 그림은 받은 형식의 확장자를 붙여 둔다. 절대 주소(htex://, https://)로 부르는 것과 위로 나가는 주소(../)는 그대로 둔다.
  같은 이름 파일이 있으면 덮어쓰기·있는 파일은 두기·취소를 묻는다. 가져오지 못한 것은 목록으로 알린다.
  저장하면 탭은 저장한 로컬 파일을 보여 주고 편집을 이어 간다.
- **원격 문서의 \input 보기** (이번에 함께 고침): 지금까지 원격 문서의 `\input` 등은 "파일을 찾을 수 없다" 경고였다.
  이제 뷰어가 파싱 중 못 찾은 상대 주소를 모아(`loader.MISSING`) 같은 서버에서 가져온 뒤 다시 해석한다
  (최대 40개, 깊이 6, 파일마다 5분 기억). 파서는 여전히 네트워크에 닿지 않는다 (가져오기는 뷰어의 일).

## 확인 필요
- 미리보기는 페이지를 다시 불러 그린다. 아주 큰 문서는 입력할 때마다 잠깐 깜박일 수 있다 (해석 2초 상한은 그대로).
- 진단 줄 번호는 본문 파일 기준이다. `\input` 한 파일 안의 오류도 본문의 같은 줄 번호에 표시될 수 있다 (진단에 파일 이름이 없음).
- 편집기 안에서 미리보기 위치로(또는 반대로) 옮겨 가는 동기화, 명령어 자동 완성은 다음 단계 후보.
- 로컬 "다른 이름으로 저장"은 본문 파일만 쓴다 (같은 폴더의 `\input` 파일은 따라가지 않음).
- 원격 문서가 다른 문서로 거는 링크(`\href{b.htex}`)·전사는 사본에 가져오지 않는다.
