# P 단계: 화면 글자 영어·한국어 — 결정과 확인 필요

## 정한 것
- **원문은 한국어 그대로** 코드에 두고 `tr("…")` 로 감싼다. 영어는 `htex/i18n_en.py` 의 표 (한국어 → 영어).
  gettext·Qt Linguist 대신 이 방식: 의존성이 없고, 지금까지의 코드·테스트를 그대로 읽을 수 있다. 언어가 둘뿐이다.
- **언어 고르기**: 보기(⋮) › "언어 · Language" (시스템 언어 · 한국어 · English, 다시 시작하면 적용) →
  환경 변수 `HTEX_LANG` → 운영체제 화면 언어 (`QLocale.uiLanguages`, Qt 가 없으면 LANG 계열).
  **한국어가 아니면 영어.** 언어 메뉴 이름은 한국어 화면에서 "언어 · Language" (잘못 골라도 찾게).
- **문서 안 이름**(그림·표·정리·증명·참고문헌·요약·핵심어·각주, 진단 목록)은 화면 언어가 아니라 **문서 언어**:
  본문 글자 중 한글이 1/5 이상이면 한국어. `<html lang>` 도 그것. 영어 논문은 한국어 화면에서도 "Figure 1".
  `\cref` 이름은 K 단계대로 영어.
- **interact.js** 글자(매개변수, 불러오는 중…)는 `<html lang>` 을 따른다.
- **macOS**: Info.plist 에 `CFBundleLocalizations` (en, ko), 개발 지역 en. 서비스·숨기기 같은 시스템 메뉴가 사용자 언어로.
  한국어일 때는 Qt 자체 번역(qtbase_ko: 입력 상자의 OK·Cancel 등)도 불러온다.
- 처음 실행 때 넣는 기본 북마크 이름("시작하기")은 그때의 화면 언어로.
- `htex build`·`htex serve`·명령줄 메시지도 같은 `tr()` (운영체제 언어).

## 확인 필요
- 일본어·중국어 등은 영어로 나온다. 번역 표를 더하면 된다 (`EN` 과 같은 꼴의 표 + `_norm`).
- 문서 언어 판정은 글자 비율. `\usepackage[korean]{babel}`·`kotex` 같은 명시 신호는 아직 보지 않는다.
