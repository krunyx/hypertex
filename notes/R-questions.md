# R 파일 열기 (v0.8.0) — 결정과 확인 필요 항목

## 1. 결정

- **파일 단추 자리**: 도구줄의 홈(⌂) 단추와 주소창 사이. 새 동작을 만들지 않고 기존 `act_open`(파일 열기, Ctrl+O)을
  그대로 단다. 아이콘은 열린 폴더 모양(`folder_open`, Material 아이콘과 같은 꼴)으로 새로 넣었다.
- **놓기 영역은 창 전체**: 주소창(`AddressEdit.files_dropped`), 창(`ViewerWindow.dropEvent`), 페이지 모두.
  웹 엔진의 안쪽 렌더 위젯은 놓기를 스스로 받으므로 `FileDropFilter` 로 **로컬 파일 놓기만** 가로채 창이 연다.
  렌더 위젯이 다시 만들어질 때(렌더 프로세스 재시작)를 위해 `ChildAdded` 때 필터를 다시 단다.
- **글자·웹 주소 끌기는 건드리지 않는다**: `dropped_paths` 는 로컬 파일만 고르고(폴더 제외), 없으면 원래 처리로 넘긴다.
- **여러 파일**: 첫 파일은 지금 탭(편집 중인 탭이면 `navigate` 규칙대로 새 탭), 나머지는 뒤쪽 새 탭.
  Chrome 은 페이지에 놓으면 지금 탭, 탭 줄 사이에 놓으면 그 자리 새 탭인데, 자리 계산은 하지 않았다.
- **확장자 검사는 하지 않는다**: 열 수 없는 파일은 주소창에 경로를 친 것과 같이 `ViewerCore.input_to_url` 의 진단을 따른다.

## 2. 확인 필요

- 원문 편집기(왼쪽 칸)에 파일을 놓으면 지금은 편집기 쪽 웹 엔진이 받는다. 편집기에도 같은 필터를 달지 정할 것.
- 탭 줄 두 탭 사이에 놓으면 그 자리에 새 탭을 여는 Chrome 동작은 다음 버전 후보.

## 3. 북마크 가져오기 (v0.8.1) — 결정

- **중첩 폴더**: 북마크 폴더 안에 폴더를 둔다 (전에는 한 단계만). 깊이는 `MAX_DEPTH`(8) 에서 자르고, 가져올 때
  더 깊은 폴더의 북마크는 버리지 않고 위 폴더로 올린다. 북마크바 폴더 메뉴는 하위 폴더를 하위 메뉴로 보이고,
  하위 메뉴는 처음 열 때 채운다 (북마크가 수천 개여도 빨리 뜨게). ☆ 상자의 폴더 목록은 "A › B" 경로로 보인다.
  `tests/unit/test_L_bookmarks.py` 의 "중첩 폴더를 버린다" 검사를 "중첩 폴더를 둔다"로 바꿨다.
- **두 길**: (1) Chromium 계열 프로필의 `Bookmarks` JSON 을 직접 읽는다 (Chrome, Edge, Brave, Whale, Vivaldi,
  Chromium; 프로필 이름은 `Local State`). 브라우저가 열려 있어도 읽기만 하므로 괜찮다.
  (2) 모든 브라우저가 내보내는 Netscape HTML 북마크 파일. 북마크바는 `PERSONAL_TOOLBAR_FOLDER="true"` 표시,
  표시가 없으면(Safari) 이름이 Favorites·Bookmarks bar 인 폴더, 그것도 없으면 맨 위 항목 전체.
- **어디에 넣나 (Chrome 의 가져오기와 같다)**: 북마크바가 비었거나 처음 넣어 둔 기본 북마크뿐이면 가져온
  북마크바 항목을 그대로 북마크바 끝에, 아니면 "<브라우저>에서 가져옴" 폴더 하나에. 북마크바 밖의 것(기타·모바일
  북마크)은 "기타 북마크" 폴더로.
- **겹치지 않게**: 이미 있는 주소(끝의 / 차이 무시)는 건너뛴다. 다시 가져와도 늘지 않는다.
- **건너뛰는 주소**: `javascript:` 북마크릿, `chrome://`·`edge://`·`about:` 같은 브라우저 내부 주소, `data:`.
  `file://` 는 주소창에 넣는 로컬 경로로 바꾼다.
- 가져온 뒤 북마크바가 숨겨져 있으면 보이게 한다.

## 4. 확인 필요 (북마크)

- 한국어 Safari 가 표시 없이 "즐겨찾기" 이름으로 내보내는 경우는 이름으로 찾지 않는다 (화면 글자 검사
  `test_P_i18n` 이 코드 안의 한국어 문자열을 막아서). 그때는 모든 항목이 북마크바로 들어간다. 필요하면
  `test_P_i18n` 의 허용 목록에 넣고 `_BAR_NAMES` 에 더할 것.
- Firefox 의 `places.sqlite` 직접 읽기는 하지 않았다 (HTML 내보내기로 충분하다고 봄).
- 북마크 관리자(폴더 안에 새 폴더 만들기, 끌어서 옮기기)는 아직 없다. 하위 폴더는 가져오기로만 생긴다.

## 5. 세션 복원·닫은 탭 다시 열기 (v0.8.1) — 결정

- **기본은 "이전 탭 다시 열기"** (Chrome 의 기본은 새 탭 페이지지만, 로드맵에서 "재실행 시 탭 유지"로 정했다).
  ⋮ › 시작할 때 에서 "새 탭 페이지 열기"로 바꿀 수 있다 (`QSettings` 의 `startup/mode`).
- **저장**: 사용자 데이터 폴더의 `session.json` (`htex/viewer/session.py`). 탭이 바뀌면(주소·제목·순서·지금 탭·
  닫기) 0.8초 뒤에 저장하고, 창을 닫을 때 한 번 더. 그래서 강제 종료돼도 거의 마지막 상태가 남는다.
  주소는 북마크와 같은 꼴(로컬 문서는 파일 경로). 원문 보기·빈 탭·멈춘 탭은 저장하지 않는다.
- **켤 때**: 이전 탭을 같은 차례로 열고 그때의 지금 탭을 고른다. 파일을 열며 켰으면(더블클릭·`htex view a.htex`)
  이전 탭 뒤에 그 파일 (Chrome 과 같다). 새 탭 페이지 하나뿐인 세션은 없는 것으로 친다.
- **세션을 쓰는 창은 `run()` 이 만든 창뿐**: 테스트·다른 코드가 `ViewerWindow` 를 직접 만들면 저장하지 않는다
  (`session_path is None`). `HTEX_VIEWER_SESSION=0` 이면 `run()` 도 쓰지 않는다.
- **닫은 탭 다시 열기** (Ctrl+Shift+T, 탭 우클릭 메뉴, macOS 파일 메뉴): 최근 25개를 기억하고 원래 자리에 연다.
  창을 닫은 뒤(마지막 탭 닫기)의 탭은 기억하지 않는다 — 다음에 켤 때 세션으로 돌아온다.

## 6. 확인 필요 (세션)

- 창이 여러 개면 마지막에 저장한 창의 탭만 남는다 (지금 뷰어는 단일 인스턴스·창 하나가 보통).
- 탭마다의 뒤로·앞으로 기록과 스크롤 위치는 저장하지 않는다.
- 이전 탭을 모두 한꺼번에 불러온다. Chrome 처럼 고른 탭만 먼저 불러오는 지연 로딩은 탭이 많아지면 검토.

## 7. 인쇄·PDF로 저장 (v0.8.1) — 결정

- **Ctrl+P = 인쇄 대화상자** (운영체제 대화상자에서 프린터·"PDF로 저장"을 고른다). ⋮ 메뉴와 macOS 파일 메뉴에
  "PDF로 저장…"을 따로 둔다 (Chrome 은 인쇄 미리보기 안의 대상 선택이지만, 미리보기 창은 만들지 않았다).
- 편집 중인 탭은 오른쪽 미리보기를 인쇄한다. 시작 페이지·빈 탭은 인쇄하지 않는다.
- **종이**: 미국·캐나다 로캘은 Letter, 그 밖에는 A4, 여백 15mm (PDF로 저장). 인쇄는 대화상자에서 고른 대로.
- **어두운 테마여도 흰 종이에 검은 글자**: 문서 CSS 의 `@media print` 가 `:root[data-theme]` 보다 약해서 어두운
  테마에서는 검은 바탕으로 인쇄됐다. 같은 선택자를 함께 써서 인쇄에서는 밝은 색이 이기게 했다 (`htex/html/style.py`).
  웹 폴백(`htex serve`·`htex build`)의 인쇄에도 같이 적용된다.

## 8. 확인 필요 (인쇄)

- Chrome 같은 인쇄 미리보기 창(쪽 수·여백·머리글 고르기)은 없다.
- 인터랙티브 슬라이더는 인쇄할 때 지금 값 그대로 찍힌다.


## 9. 테스트 격리 (v0.8.1 릴리스 빌드에서 발견)

- v0.8.1 첫 릴리스 빌드에서 `test_R_session.py` 가 macOS·윈도에서만 실패했다. 사용자 데이터 폴더가 macOS 는
  `~/Library/Application Support`, 윈도는 `%APPDATA%` 라서 테스트가 바꾼 `HOME`·`XDG_DATA_HOME` 을 따르지 않았고,
  그래서 (1) 세션 파일을 엉뚱한 곳에 찾았고 (2) `run()` 을 부르는 다른 테스트(J)가 CI 머신의 실제 데이터 폴더에
  남긴 세션을 다시 열었다. 리눅스는 XDG 를 따르므로 통과했다.
- 고침: 환경 변수 `HTEX_DATA_DIR` 를 두었다. 있으면 데이터 폴더(북마크·세션)로 쓰고, 뷰어 설정(QSettings)도
  그 안의 `viewer.ini` 에 둔다. `tests/unit/conftest.py` 가 테스트 전체에 임시 폴더를 주고 세션 복원을 끈다
  (`HTEX_VIEWER_SESSION=0`). 세션 테스트만 둘 다 직접 켠다. 휴대용 설치(USB 등)에도 쓸 수 있다.

## 10. 수식 원문 복사 (v0.8.2) — 결정

- 원문은 MathML 의 `<annotation encoding="application/x-tex">` 와 수식 행(`tr.htex-eqrow`)의 `data-tex` 에 이미 있다.
  그래서 문서·변환기는 고치지 않고 `htex/web/interact.js` 에서 읽는다 (뷰어와 웹 폴백 모두).
- **우클릭** (뷰어): 엔진 기본 메뉴 맨 위에 "수식을 LaTeX로 복사". 페이지 스크립트가 우클릭한 수식의 원문을
  기억해 두고(`HTEX.contextMath()`), 뷰어가 메뉴를 띄울 때 읽는다. 구분 기호 없이 원문만 복사한다.
  가운데 식·align 은 그 줄의 원문 (`x&=1`).
- **골라서 복사** (뷰어와 웹): 고른 곳에 수식이 있으면 일반 글자(text/plain)에서 인라인 수식은 `$…$`,
  가운데 식은 `$$…$$`, `&` 가 있는 align 줄은 `$$\begin{aligned}…\end{aligned}$$` 로 바꾼다. 수식 하나 안에서
  일부만 골라도 그 수식 전체를 복사한다. 수식 번호는 빼고, text/html 은 브라우저가 만드는 그대로 둔다.
  수식이 없으면 브라우저 기본 복사 (KaTeX 의 copy-tex 와 같은 동작).
- 우클릭 정보 없이 기본 메뉴를 만들면(`createStandardContextMenu`) 엔진이 멈추므로, 그때는 뒤로·앞으로·
  새로고침·복사·모두 선택만 있는 메뉴를 만든다.

## 11. 링크 미리보기는 이미 있다

- 로드맵의 "상호참조·인용·각주 호버 미리보기"는 2단계(G, `interact.js` 의 `setupPreviews`)에서 이미 만들어져
  있었다: 같은 문서 참조·인용·각주 링크에 마우스를 올리거나 초점을 주면 말풍선, 다른 문서는 조각 주소로.
  `tests/unit/test_R_copy_latex.py` 가 뷰어에서 뜨는지 함께 확인한다.

## 12. 방문 기록 (v0.8.2) — 결정

- **Ctrl+H (macOS Cmd+Y)**: 기록 페이지 `htexapp://start/history` 를 새 탭에 (이미 열려 있으면 그 탭으로).
  macOS 의 Cmd+H 는 앱 숨기기라 Chrome 처럼 Cmd+Y. 날짜별(오늘·어제·날짜) 목록, 검색 칸(제목·주소, 띄어 쓴
  낱말 모두), 항목마다 ×, "방문 기록 삭제"(확인 상자). 시작 페이지와 같이 스크립트 없는 페이지이고, 열기·지우기
  링크는 창이 가로챈다 (`startpage.parse_request` 에 `/forget` 를 더했다). 이 요청들은 시작·기록 페이지 자신이 보낸
  것만 받는다.
- **저장**: 사용자 데이터 폴더의 `history.jsonl` (`htex/viewer/visits.py`), 한 줄에 한 방문, 덧붙이기만. 최대
  10,000개. 같은 주소를 30분 안에 다시 열면(새로고침·앞뒤 이동) 새 줄 없이 그 방문을 최근으로 올린다.
- **언제 남기나**: 주소가 바뀌는 순간(Chrome 과 같이 탐색이 확정될 때). 처음에는 제목 없이 남기고 제목이 정해지면
  고친다. 불러오기 끝을 기다리면 빨리 다음 페이지로 넘어갈 때 앞 방문이 빠졌다. 시작·기록 페이지, 원문 보기,
  멈춘 탭은 남기지 않는다.

## 13. 확인 필요 (방문 기록)

- 시크릿 창(기록하지 않는 창)은 없다.
- 세션 복원이 여는 탭, 다른 창에서 연 문서도 기록에 남는다 (Chrome 과 같다).
- 기록 페이지도 "빈 탭"으로 쳐서, 그 탭에서 파일을 열면 그 자리에 열린다.

## 14. 새 버전 알림 (v0.8.2) — 결정

- **자동 업데이트 대신 알림**: 설치 파일이 아직 코드 서명되지 않아, 몰래 내려받아 바꾸면 운영체제 보안 경고와
  위험이 크다. 그래서 GitHub `releases/latest`(초안·시험판 제외)를 확인하고, 지금보다 새 버전이면 도구줄 ⋮ 왼쪽에
  "업데이트" 단추(Chrome 의 알약 단추)를 띄운다. 누르면 받기 페이지(krunyx.com/hypertex/download/)를 연다.
- **언제**: 켜고 5초 뒤, 마지막 확인에서 하루가 지났을 때만 (`update/last_check`). 별도 스레드라 창이 멈추지
  않는다. 실패하면 조용히 넘어가고, 사용자가 ⋮ › 업데이트 › 업데이트 확인을 눌렀을 때만 알린다.
- **끄기**: ⋮ › 업데이트 › 업데이트 자동 확인 (macOS 는 도움말 메뉴에도). 환경 변수 `HTEX_UPDATE_CHECK=0` 이면
  자동 확인을 하지 않는다 (테스트는 conftest 가 끈다). `HTEX_UPDATE_URL` 로 확인 주소를 바꿀 수 있다.
- **보내는 것**: 요청 하나, `User-Agent: HyperTeX/<버전>` 뿐.
- 시험판 꼬리표가 붙은 버전("0.9.0-rc1")은 새 버전으로 치지 않는다.

## 15. 확인 필요 (업데이트)

- 코드 서명·공증을 마치면 진짜 자동 업데이트(내려받아 바꾸기)를 검토할 것. macOS 는 Sparkle 같은 틀이 흔하다.
- 받기 페이지가 운영체제별 파일을 바로 고르게 해 주면 단추 한 번으로 끝난다 (홈페이지 쪽 일).


## 16. 방문 기록 제목 (v0.8.2, 윈도 CI 에서 발견)

- 웹 엔진은 페이지 제목이 정해지기 전에 주소(`htexapp://doc-…/a.htex`)를 제목처럼 알려 준다. 윈도에서는 이 순서가
  달라 기록 제목이 내부 주소로 남았다 (PR #18 의 윈도 py3.11 테스트). 지금 주소와 같거나 `://` 가 든 낱말 하나뿐인
  제목은 기록 제목으로 쓰지 않는다. 제목이 없으면 기록 페이지는 주소를 대신 보인다.
- 그 뒤 v0.8.2 릴리스 빌드의 윈도 py3.13 에서 반대 차례도 나왔다: **새 페이지 제목이 주소보다 먼저** 와서 버려지고
  기록 제목이 비었다. 그래서 탭마다 "마지막으로 남긴 방문"(`_visit_addr`·`_visit_titled`)과 "아직 주인 없는
  제목"(`_pending_title`)을 들고 맞춘다. 주소가 앞 페이지인데 불러오는 중에 다른 제목이 오면 새 페이지 제목으로
  미뤄 두었다가 주소가 바뀔 때 쓴다. 불러오기가 끝났을 때의 제목이 마지막 판단이다. 두 차례를 모두 흉내 내는
  테스트(`test_titles_match_pages_in_either_signal_order`)가 운영체제와 상관없이 확인한다.
